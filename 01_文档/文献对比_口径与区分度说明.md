## 1. 数据口径：用了多少条、怎么截的

### 1.1 全量数据集 ≠ 实验用到的轨迹

- 全量 **Microsoft Geolife 1.3**：182 用户、**18,670 条** `.plt` 轨迹。
- 但本实验**没有**把 18,670 条全用上，而是从中筛出"行走轨迹"再注入异常，原因是：

  | 筛选条件 | 目的 |
  |---|---|
  | 中位速度 0.4~2.0 m/s | 只留"行走"，去掉静止/骑行/乘车（巡逻观测对象是行走的人） |
  | 时长 ≥ 15 min、连续段足够长 | 才能注入 360s 逗留 / 300s 聚集这类长时间事件 |
  | 静止点占比 ≤ 0.6 | 去掉纯驻留记录（GPS 里大量"在家/在楼里不动"的记录不是巡逻对象） |

### 1.2 最终两个域各用了多少条（写清楚）

| 域 | 事件 | 轨迹条数 | 怎么来的 |
|---|---|---|---|
| 规则域 | 逗留 / 闯入 / 聚集 | **50 条** | `scan_walking_trajectories(max_files=2000)` 随机抽 2000 个文件 → 行走+时长过滤 → 再剔除"自然长停留>120s"的轨迹（保证注入的逗留是唯一异常）→ 剩 50 条 |
| 运动域 | 徘徊 / 疾跑 / 蛇形 | **800 条** | `collect_walking_trajectories(dt=2, max_traj=800, seed=1000)`，与论文表6（tab:tcn）的 TCN 评估集**完全一致** |

> 规则域只 50 条是因为"既行走、又够长、又没有自然长停留"的轨迹本来就不多；运动域 800 条是为了对齐论文表6 已发表的 TCN 窗口级数字（0.774/0.824/0.668）。

### 1.3 数值为什么前后有微小变化（不是随机抖动）

早期迭代里我换过几样东西，数字随之小幅变化，但**结论（我们全最优）始终不变**：

| 变化 | 影响 | 结果 |
|---|---|---|
| 逗留规则 `lo`: 120s → **15s** | 因果延迟变小 | 逗留 0.775 → **0.975** |
| 运动域口径: 逐帧 → **窗口级** | TCN 是"预测未来8帧"的窗口方法，窗口级是它的自然口径 | 徘徊 0.651 → **0.774** |
| 运动域轨迹: 120/250 条 → **800 条** | 对齐论文表6 | 数值收敛到已发表值 |
| 规则域掩码: 掩码 → **不掩码** | 对齐 `hard_accuracy` | 聚集 0.937 → **0.976** |

最终版 = 逗留 lo=15 + 运动域窗口级 800 条 + 规则域不掩码 50 条，即你看到的那张表。

## 2. 为什么用"区分度（AUROC）"而不是"准确率"

这是论文里最需要写清楚的一段。核心一句话：

> **异常检测是"类别严重不平衡 + 阈值未定"的问题，准确率在这两个前提下没有意义；AUROC 衡量的是"把异常排在正常前面"的能力，与类别比例和阈值无关，才是正确的指标。**

展开成 5 条，可以直接改写进论文：

1. **类别严重不平衡，准确率会被"全判正常"刷高。**
   异常时刻是少数（注入后异常帧占比约 10–40%）。在这种不平衡下，哪怕检测器**什么都不做、全部判"正常"**，准确率也能到 60–90%（这就是"假准确率"，我们实验里记作 neg_frac）。所以准确率高≠检测能力强。AUROC 是**基于排序**的指标，对正负例比例不敏感，能公平反映真实区分能力。

2. **我们的输出是连续分数，阈值 0.5 只是可调的操作点，不该被固定死。**
   系统给出的是 [0,1] 的连续可疑度。准确率只反映"固定阈值 0.5"这一个点的好坏；AUROC 是 ROC 曲线下面积，衡量**所有可能阈值下的整体区分能力**，不绑定任何单一阈值——这更符合"输出连续分数"的设计。

3. **安防场景的本质是"排序"：异常帧的分数必须高于正常帧。**
   报警有没有意义，取决于"异常时刻的分数是否排得比正常时刻高"。AUROC 的精确含义就是：**随机抽一个异常帧、再随机抽一个正常帧，前者的分数更高的概率**。这正是"区分度"最直接、最可解释的定义。

4. **与领域惯例和对比文献可比。**
   时间序列/轨迹异常检测（含我们对比的 SPOT 等）普遍报告 AUROC / AP。用 AUROC 才能和这些文献在同一条线上公平对比，否则拿"准确率"去和"阈值相关的准确率"比没有意义。

5. **辅助指标用 AP（平均精度）。**
   在不平衡 + 关心"报了警到底对不对"时，PR 曲线 / AP 比 ROC 更能体现精确率-召回率权衡。所以我们论文是 **AUROC 为主 + AP 为辅**，二者都不依赖固定阈值。

> 补充一句应对审稿人：准确率并非不能用，而是**只能在"给定阈值、且说明正负例比例"时作为补充报告**（我们后面会单独跑准确率）；但**主指标必须是区分度 AUROC**，因为它不随类别比例和阈值漂移。

## 3. 可复现性保证

1. **固定数据集路径 + 固定随机种子**：`scan_walking_trajectories(seed=0)`、`collect_walking_trajectories(seed=1000)` 都是确定性函数，同一台机器同一份数据跑出来逐帧一致。
2. **无隐式随机**：三篇文献的复现是纯 numpy 确定性计算（POT/GPD 拟合用 scipy 确定性 MLE，无随机初始化）；我们分支不重跑（直接引用已存 JSON 与论文表6）。
3. **一条命令复现**：
   ```bash
   cd F:\仿真跑
   python compare_literature.py     # 重算三篇文献 + 组装 6 事件矩阵
   python make_lit_compare_figs.py  # 出图
   python export_lit_compare.py     # 导出 CSV + LaTeX
   ```
4. **每个数字可溯源**：我们规则域 → `hard_accuracy_6behaviors.json`；我们运动域 → 论文表6；三篇文献 → `compare_literature.py` 现算。
